# pseudo-jepa, v2
<!-- id: v2 · chapter: Overview -->

> **v2 is training now; results are pending.** This tab puts it next to v1 and next to the research model it is closest to, Meta's VL-JEPA (Chen et al., 2025, [arXiv 2512.10942](https://arxiv.org/abs/2512.10942)).

v2 swaps v1's from-scratch encoders for two frozen, pretrained ones, V-JEPA 2 for photos and EmbeddingGemma for captions, and only trains the predictor in between. That is VL-JEPA's layout, with roughly a seventieth of its trainable weights.

## The three side by side
<!-- id: compare · chapter: Comparison -->

| | **v1** (trained) | **v2** (training) | **VL-JEPA** (Meta FAIR) |
|---|---|---|---|
| Idea | pick the right caption out of the batch | predict the caption's embedding from a partly hidden photo | predict the text's embedding from video or a photo, plus a query |
| Image encoder | from scratch: 4 conv blocks + 6 Transformer blocks, 128 px | **V-JEPA 2 ViT-L, frozen**, 256 px, 16 × 16 patches pooled to 8 × 8 | **V-JEPA 2 ViT-L, frozen** (304M), 256 px |
| Text side | from scratch: 6 Transformer blocks, 7,441-word vocabulary | **EmbeddingGemma-300M, frozen** | **EmbeddingGemma-300M, trained** at 0.05 × the learning rate |
| What it predicts | one 256-number vector per caption | the **average** of the image's 5 caption embeddings (768 numbers) | the target text's embedding, in a 1,536-number shared space |
| Predictor | 2 Transformer blocks + accumulator q | 6 Transformer blocks (width 384) + accumulator q, 2-D sin-cos positions | last 8 layers of Llama-3.2-1B, reading visual tokens + a text query |
| Hiding | nothing | 4 blocks of 15–20% of the grid, about 2/3 hidden; the frozen encoder only sees the visible patches | nothing |
| Loss | InfoNCE, both directions | **L2**: squared distance to the target, no wrong answers | InfoNCE, both directions |
| What stops collapse | 255 wrong captions per batch | the target comes from a frozen encoder, so it cannot move | wrong answers in the batch |
| Trained | 14.1M (everything) | **11.3M** (predictor only) | about 790M (predictor + text encoder) |
| Data | Flickr30k: 29,000 photos | Flickr30k: 29,000 photos, random flips | Datacomp, YFCC-100M, Action100M, then 25M+ fine-tuning samples; 3.3–3.6B seen |
| Batch, steps | 256 × 22,600 (200 epochs) | 512 × 1,680 (30 epochs) | 24,000 × 100k for photos alone, then video |
| Hardware | one Mac, 3.4 h | one Mac, about 4 s a step | 192 H200s, about 4 weeks |

## Where v2 sits
<!-- id: sits -->

- **Closer to VL-JEPA than v1 is.** Same frozen photo encoder, same text model, same "predict the text's embedding" output. v1 shared only the idea of a predictor.
- **Closer to a classic JEPA than VL-JEPA is, in one way.** v2 has no wrong answers: it regresses straight onto a fixed target and relies on the target being frozen. VL-JEPA, despite the name, still uses a contrastive loss, and trains its text encoder.
- **Its hiding is borrowed from I-JEPA** (Assran et al., 2023): the same four-block sampler, 15–20% each, and the same weight-decay ramp from 0.04 to 0.4.
- **What it gives up:** no text query (VL-JEPA can answer questions about a photo; v2 only captions), one frame instead of video, and a regression target that averages five captions into one, so it can never match a single caption exactly.

## How it will be judged
<!-- id: judged · chapter: Results -->

| | **v1** | **v2** | **VL-JEPA** |
|---|---|---|---|
| Photo → caption, R@1 / R@5 / R@10 (Flickr30k val, 5,070 captions) | 14.6% / 32.9% / 45.0% | pending | not reported |
| Caption → photo, R@1 / R@5 / R@10 (1,014 photos) | 10.7% / 27.9% / 37.5% | pending | not reported |
| Headline numbers | Flickr30k only | Flickr30k only | 61.6% ImageNet zero-shot after the photo stage; 63.7 average R@1 on 8 text-to-video retrieval sets |

VL-JEPA's numbers are on other benchmarks, so they are context, not a target. The fair test is v2 against v1 on the same 1,014 validation photos.
